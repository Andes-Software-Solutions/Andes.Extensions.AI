# 0.13.0

**Tag:** `v0.13.0` · **Date:** 2026-10-31

All changes since [`v0.12.0`](v0.12.0.md).

A dependency-floor release with one small source change. The Agent satellite's floor rises to `Microsoft.Agents.AI` 1.27.0, the MCP satellite's floor rises to `ModelContextProtocol.Core` 2.3.0, and the three satellites depend on core `>= 0.13.0`. The MCP bump is source-breaking for this repo: the MCP C# SDK 2.3.0 made `McpClient.ServerInfo` nullable, so `Andes.Extensions.AI.Mcp` now tolerates a server that reports no identity. No public signatures changed. All four packages ship at 0.13.0 in lockstep. This release supersedes Dependabot PR #29 ("Bump the nuget-stable group with 5 updates", opened 2026-10-31), which carries five of the six pin moves below (not `ModelContextProtocol`), not the `ServerInfo` fix, and not the version bump. It moved `ModelContextProtocol.Core` to 2.3.0 but left `ModelContextProtocol` at 2.2.0, whose nuspec requires Core `[2.2.0]` exactly.

## Changed

- **`ModelContextProtocol` and `ModelContextProtocol.Core` 2.2.0 → 2.3.0** (`Directory.Packages.props`): the MCP satellite's new floor, `ModelContextProtocol.Core >= 2.3.0`. Upstream `v2.3.0` (github.com/modelcontextprotocol/csharp-sdk, published 2026-10-20) has one breaking change, `McpClient.ServerInfo` becoming nullable (#1903, see Fixed). It also preserves the order of listed tools, prompts, and resources (#1924; this repo's tests look tools up by name), closes server stdin before waiting for a graceful stdio exit (#1838), and preserves numeric progress tokens in `RequestOptions` serialization (#1832). `ModelContextProtocol.Core` 2.3.0 declares `Microsoft.Extensions.AI.Abstractions` 10.11.0, which equals the repo's pin, so transitive pinning causes no downgrade.
- **`Microsoft.Agents.AI` 1.25.0 → 1.27.0** (`Directory.Packages.props`): the Agent satellite's new floor, `Microsoft.Agents.AI >= 1.27.0`. Upstream `dotnet-1.26.0` (2026-10-23) and `dotnet-1.27.0` (2026-10-30), github.com/microsoft/agent-framework, list these breaking items: an AgentServer dependency update (#9721), `DefaultHttpRequestHandler` redirect client changes (#9711), and a docker parameter rename (#9453). None touch the APIs the Agent satellite calls: `AIAgentBuilder.Use(...)`, `AsAIFunction(...)`, `DelegatingAIAgent.RunCoreAsync`/`RunCoreStreamingAsync`, or `AgentResponse.Usage`. Version 1.27.0 declares `Microsoft.Extensions.AI` 10.10.0 and `Microsoft.Extensions.AI.Abstractions` 10.10.1; the repo's 10.11.0 pins are higher, so there is no downgrade. `Microsoft.Agents.AI.Abstractions` moves 1.25.0 → 1.27.0 as a transitive side effect (not pinned by this repo).
- **`Microsoft.Extensions.Configuration.Binder` / `.Json` and `Microsoft.Extensions.Hosting` 10.0.13 → 10.0.14** (`Directory.Packages.props`): referenced only by the sample apps, the test projects, and the TestMcpServer. Nothing shipped references them.

## Fixed

- **`Andes.Extensions.AI.Mcp` tolerates a server that reports no identity.** MCP C# SDK 2.3.0 changed `McpClient.ServerInfo` from `Implementation` to `Implementation?` (upstream #1903). It is `null` on `2026-07-28` connections when the server omits its optional identity from `server/discover`. This was source-breaking here: `GetServerDisplayName` raised CS8602 under warnings-as-errors.
  - `WithTracking(tool, client)` and `WithTracking(tools, client)` now treat a missing identity, or an empty name, as "the wrapper carries no server name". Top-level classification then continues to `serverNameResolver`, then `defaultServerName`. No placeholder is hard-coded, so a configured default or resolver is honored. The `serverNameResolver` row of the precedence table in [`docs/mcp.md`](../docs/mcp.md) now covers this case too.
  - A server with an empty title and an empty name used to make `WithTracking(tool, client)` throw `ArgumentException`; it now falls back the same way.
  - The explicit `WithTracking(tool, string serverName)` overload still rejects `null` and empty strings.
  - **Known limitation for nested calls.** An invocation nested inside another tool or an agent goes through `ChatProgress.BeginToolScope`, which bypasses `ToolClassifier`. A nameless wrapper there shows `Calling {tool} MCP` and reports a `null` `Source` (`ChatProgressUpdate.ToolSource`, `ToolCallUsage.Source`); the resolver and default do not apply. This is deliberate: resolving it would need a new core API.
  - No public signatures changed. This is the only source change in the shipped packages.

## Verification

- `dotnet build Andes.Extensions.slnx --configuration Release --no-incremental` succeeds with 0 warnings and 0 errors.

- `dotnet test --configuration Release --no-build` passed 178 of 178 with 0 skipped: 168 unit tests (core 82, UI 31, Agent 28, MCP 27) and 10 Azure OpenAI integration tests run for real (core 5, MCP 2, Agent 3). - `dotnet list package --outdated` reports no updates for any of the 14 projects, `--vulnerable --include-transitive` reports none for all 14, and `--deprecated` reports only `xunit` 2.9.3.
