# 0.12.0

**Tag:** `v0.12.0` · **Date:** 2026-10-20

All changes since [`v0.11.0`](v0.11.0.md).

Another dependency-floor release, same nature as 0.9.0 through 0.11.0: the floor of `Microsoft.Extensions.AI` and `Microsoft.Extensions.AI.Abstractions` rises to 10.11.0 in all four packages, the Agent satellite's floor rises to `Microsoft.Agents.AI` 1.25.0, the SDK band in `global.json` moves to 10.0.402, and `OpenAI` deliberately stays at 2.14.0 because that is still the version `Microsoft.Extensions.AI.OpenAI` 10.11.0 declares and the latest on nuget.org — no source changed, no public API changed, and all four packages ship at 0.12.0 in lockstep with the satellites depending on core `>= 0.12.0`. This release supersedes Dependabot PR #26 ("Bump the nuget-stable group with 8 updates", opened 2026-10-17), which carries eight of the nine pin moves below (everything except `Microsoft.Extensions.AI`) but not the rewritten pin comment, the `global.json` move, or the version bump.

## Changed

- **`Microsoft.Extensions.AI` 10.10.0 → 10.11.0, `Microsoft.Extensions.AI.Abstractions` 10.10.1 → 10.11.0, and `Microsoft.Extensions.AI.OpenAI` 10.10.1 → 10.11.0** (`Directory.Packages.props`, uncommitted): upstream `v10.11.0` (github.com/dotnet/extensions, published 2026-10-15). Its AI fixes: yield the final image when streaming with `HostedImageGenerationTool` (#7774); the default tool-rejection message now states the decision is final (#7784); removal of an obsolete OpenAI `JsonPatch` workaround (#7815); empty model IDs in streaming responses are ignored (#7816); `FunctionInvocationContext.Terminate` is honored when the function throws (#7801); `ChatResponseUpdate.Clone` no longer drops `ContinuationToken` (#7699); and non-base64 data URIs in `DataContent` are decoded (#7798). Its only breaking change to an experimental API is the HTTP latency telemetry rename `AddHttpLatencyTelemetry` → `AddHttpServerLatencyTelemetry` (#7730), which this repo does not use. Checked against the sources: nothing in the shipped packages sets `Terminate`, uses `FunctionInvoker`, calls `ChatResponseUpdate.Clone()`, or reads `ContinuationToken` (the only `Clone()` is `ChatOptions.Clone()` in `ToolTrackingChatClient.WrapTools`), and `TrackingAIFunction` and `AgentTrackingAIFunction` already catch, mark the scope failed, and rethrow. `Microsoft.Extensions.AI.OpenAI` is consumed only by the samples and the integration-test projects; nothing shipped references it.
- **Consumer note: model ID on Azure OpenAI Chat Completions streams.** #7816 lives in the `OpenAIChatClient` adapter in `Microsoft.Extensions.AI.OpenAI`, which none of the four packages depends on. A consumer who also upgrades `Microsoft.Extensions.AI.OpenAI` to 10.11.0 may now see a populated `ModelId` where an empty string used to arrive on Azure OpenAI Chat Completions streams. The tracker reads `update.ModelId` as received, so the value can surface in `AssistantTurnUsage.ModelId` and `ChatUsageReport.ModelId`. This depends on upstream behavior; no test in this repo asserts on it.
- **Consumer-visible floor: `Microsoft.Extensions.AI >= 10.11.0` and `Microsoft.Extensions.AI.Abstractions >= 10.11.0` in all four packages.** The repo sets `CentralPackageTransitivePinningEnabled=true`, so the pinned versions are emitted as direct dependencies in every package's nuspec. The `Microsoft.Extensions.AI` floor rises from 10.10.0 and the Abstractions floor from 10.10.1, in core, Mcp, Agent, and UI.
- **`Microsoft.Agents.AI` 1.24.0 → 1.25.0** (`Directory.Packages.props`, uncommitted): the Agent satellite's new floor — the packed nuspec reads `Microsoft.Agents.AI >= 1.25.0`. Upstream `dotnet-1.25.0` (github.com/microsoft/agent-framework, published 2026-10-14) lists: approval reuse considerations (#9389), terminating the chat completions SSE stream with `data: [DONE]` (#8532), citations and error details in Purview checks (#9375), reasoning remnants and handoff bounce-back fixes (#9174), A2A packages to 1.0.0-preview3 (#9386), automatic rejection of tool-approval requests that never receive a response (#9152), closed-list workflow questions (#9202), preserving the agent continuation token when wrapped with `UseOpenTelemetry` (#8265), isolating the Foundry toolbox response cache (#8848), and two breaking changes: decoupling Cosmos chat metadata from the partition-key strategy (#9214) and Harness concise progress (#9004), the latter reverted by #9147 in the same release. None of this touches the APIs the Agent satellite calls: `AIAgentBuilder.Use(...)` function-invocation middleware, `AsAIFunction(...)`, `DelegatingAIAgent.RunCoreAsync`/`RunCoreStreamingAsync`, or `AgentResponse.Usage`. The Cosmos and Harness changes are not used; #9152 only changes approval binding and the Workflows/Harness hosts, and the satellite has no approval handling; #9174 is limited to Workflows handoff filtering, which the satellite does not use. The 1.25.0 nuspec still depends on `Microsoft.Extensions.AI` 10.10.0 and `Microsoft.Extensions.AI.Abstractions` 10.10.1; the repo's 10.11.0 pins are higher, so with transitive pinning there is no downgrade and the floor consumers see is 10.11.0. A transitive floor moves as a result (not pinned by this repo): `Microsoft.Agents.AI.Abstractions` 1.24.0 → 1.25.0.
- **`Microsoft.Extensions.Configuration.Binder` / `.Json` and `Microsoft.Extensions.Hosting` 10.0.12 → 10.0.13, `Microsoft.NET.Test.Sdk` 18.10.1 → 18.11.0, and `xunit.runner.visualstudio` 4.0.0 → 4.0.1** (`Directory.Packages.props`, uncommitted): referenced only by the sample apps, the test projects, and the TestMcpServer — nothing shipped references them.
- **`OpenAI` stays at 2.14.0 on purpose.** The nuspec of `Microsoft.Extensions.AI.OpenAI` 10.11.0 declares `OpenAI >= 2.14.0` for every target framework, and 2.14.0 is the latest `OpenAI` on nuget.org, so the pin already equals the version the adapter compiles against. Only the comment above the pin in `Directory.Packages.props` changed, to cite `Microsoft.Extensions.AI.OpenAI` 10.11.0 instead of 10.10.1 (uncommitted). The `OpenAI` ignore rule in `.github/dependabot.yml` and the `OPENAI001` comments in `samples/Andes.Extensions.AI.Demo.Responses` and `tests/Andes.Extensions.AI.Integration.Test` remain accurate and are unchanged.
- **`global.json`**: SDK `10.0.401` → **`10.0.402`** (uncommitted; `rollForward: latestFeature` unchanged), the latest .NET 10 SDK per the .NET releases index (`latest-sdk` 10.0.402 alongside runtime 10.0.13, released 2026-10-13, flagged `security=true`; SDKs 10.0.402 and 10.0.113). `nuget.yml` reads `global-json-file`, so CI follows without a workflow change.
- **Every other pin was already the latest stable and is unchanged**: `ModelContextProtocol` / `.Core` 2.2.0, `Azure.AI.OpenAI` 2.1.0 (every newer version is a beta, up to 2.9.0-beta.1), `Spectre.Console` 0.57.2 (0.57.3 exists only as alphas), `coverlet.collector` 10.1.0, `Xunit.SkippableFact` 1.5.85, and `xunit` 2.9.3. `dotnet list package --deprecated` flags `xunit` 2.9.3 as "Legacy", superseded by `xunit.v3`; that migration remains deferred to its own change, and the transitive `xunit.analyzers` 2.2.0 offered by `--outdated` belongs to the v3 line. `dotnet list package --vulnerable --include-transitive` reported no vulnerable packages in any project.
- **Transitive floors that moved as a side effect** (from a before/after diff of `dotnet list package --include-transitive`; none are pinned by this repo, beyond the `Microsoft.Agents.AI.Abstractions` move already noted above). Via `Microsoft.Extensions.AI` 10.11.0, in the shipped packages: `Microsoft.Extensions.Caching.Abstractions`, `Microsoft.Extensions.DependencyInjection.Abstractions`, `Microsoft.Extensions.Logging.Abstractions`, `Microsoft.Extensions.Primitives`, and `System.Numerics.Tensors` 10.0.12 → 10.0.13. Everything else moves only in the samples, tests, and TestMcpServer: the Configuration, Hosting, Logging, Options, Diagnostics, DependencyInjection, and FileProviders family (plus `Microsoft.Extensions.FileSystemGlobbing` and `System.Diagnostics.EventLog`) 10.0.12 → 10.0.13, and `Microsoft.CodeCoverage` and `Microsoft.TestPlatform.ObjectModel` / `.TestHost` 18.10.1 → 18.11.0. `OpenAI`, `System.ClientModel`, and `System.Memory.Data` did not move.
- **Docs updated to the actual floors** (uncommitted): [`docs/agents.md`](../docs/agents.md) now states core `>= 0.12.0` and `Microsoft.Agents.AI >= 1.25.0` (previously `>= 0.11.0` / `>= 1.24.0`); [`docs/mcp.md`](../docs/mcp.md) now states core `>= 0.12.0` (previously `>= 0.11.0`); [`docs/ui.md`](../docs/ui.md) now states core `>= 0.12.0` (previously `>= 0.11.0`). The `AGENTS.md` project section now says the four packages are at 0.12.0.
- **All four packages version in lockstep at 0.12.0; the satellites depend on core `>= 0.12.0`.** No public API changes, no code changes (no `.cs` file changed).
