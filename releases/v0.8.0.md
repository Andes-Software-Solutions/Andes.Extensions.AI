# 0.8.0

**Tag:** `v0.8.0` · **Date:** 2026-08-20

All changes since [`v0.7.0`](v0.7.0.md).

The UI contract had no supported slot for data an application wants to attach to a specific event without the package's help — the running example is an API that persists each turn's answer as a transcript document and wants to hand its client the persisted message id on the `Finished` frame, so the UI can offer per-message actions (rating, a permalink) without a transcript refetch ([#14](https://github.com/Andes-Software-Solutions/Andes.Extensions.AI/issues/14)). Nothing stopped an application from splicing extra JSON properties into the payload itself, but that workaround diverges from the shipped TypeScript contract — the `.ts` file the package ships no longer matches the bytes actually on the wire, and the C# and TypeScript folds have no shared rule for what happens to those extra properties as events accumulate into a snapshot.

## Added

- **`AssistantUiEvent.Metadata`** (`Andes.Extensions.AI.UI/AssistantUiEvent.cs`): an optional `IReadOnlyDictionary<string, string>?` `init` property, added last on the record. The package neither reads nor interprets it; the mapper (`ToUiEventsAsync`, `ToUiEvent`, `ToSnapshot(ChatUsageReport)`) always leaves it `null` — an application attaches values by rewriting events it re-streams, e.g. `uiEvent with { Metadata = new Dictionary<string, string> { ["messageId"] = id } }`.
- **`AssistantStatusSnapshot.Metadata`** (`Andes.Extensions.AI.UI/AssistantStatusSnapshot.cs`): the accumulated counterpart, also last on the record. When the snapshot comes from `AssistantStatusReducer`, it's the running merge of every folded event's `Metadata`.
- **The merge in `AssistantStatusReducer.Apply`** (`Andes.Extensions.AI.UI/AssistantStatusReducer.cs`): a new copy-on-write `MergeMetadata` step runs on every call, before the `switch` on `Kind` — so every kind, including ones this reducer doesn't recognize, still contributes its metadata. The merge is a dictionary overlay with last write per key winning across the whole request; a `null` or empty bag is a no-op that reuses the existing accumulated instance (no copy, no allocation); an earlier returned snapshot's `Metadata` is never mutated by a later merge.
- **`metadata?: Record<string, string>` on both TypeScript interfaces** (`Andes.Extensions.AI.UI/typescript/andes-assistant-ui.ts`): added last on `AssistantUiEvent` and `AssistantStatusSnapshot`. A new `mergeMetadata` helper in `foldAssistantEvents` applies the identical merge-before-`switch` rule via object spread, including through the `switch`'s `default` arm for unknown kinds — keeping the two folds in lockstep by construction, not by convention.
- **Docs updated**: [UI status contract](../docs/ui.md) documents the wire field, the accumulated snapshot field, the mapper's never-populates rule, the reducer's merge order, and the privacy posture of an application-owned bag; the [UI contract example](../docs/examples/ui-contract.md) extends its SSE producer with an `AttachMessageIdAsync` step that rewrites the `Finished` event and shows the TypeScript and Blazor consumers reading `metadata?.["messageId"]` back; the [`Andes.Extensions.AI.UI` README](../Andes.Extensions.AI.UI/README.md) gets a Notes bullet summarizing the same.
- **Additive and wire-compatible.** A field absent on the wire today stays absent: `Metadata` serializes as `null`-omitted, same as every other optional field on `AssistantUiJsonContext`, so a 0.7 consumer sees byte-identical JSON when a producer doesn't set it. Only an application choosing to set `Metadata` changes what's on the wire.
- **All four packages version in lockstep at 0.8.0; the satellites depend on core >= 0.8.0. No dependency-pin changes.**

## Verification

New unit coverage in `tests/Andes.Extensions.AI.UI.Unit.Test/` pins the merge order, immutability, and serialization rules: `Apply_MetadataOnStatusEvent_CarriesOntoSnapshot`, `Apply_MetadataAcrossEvents_MergesWithLastWriteWinningPerKey`, `Apply_NullOrEmptyMetadata_LeavesAccumulatedMetadataUnchanged`, `Apply_EmptyMetadataOnly_LeavesSnapshotMetadataNull`, `Apply_UnknownKind_StillMergesMetadata`, `Apply_LaterMetadataEvent_DoesNotMutateEarlierSnapshot`, and `Apply_CallerMutatedEventDictionary_SnapshotKeepsOriginalValues` (all in `AssistantStatusReducerTests`); `SerializeRoundTrip_EventWithMetadata_PreservesEntriesWithVerbatimKeys` and `Serialize_SnapshotWithMetadata_EmitsCamelCasePropertyWithVerbatimKeys`, plus the extended `Serialize_Snapshot_UsesCamelCaseStringEnumsAndOmitsNulls` (now also asserting `metadata` is omitted when `null`) (in `AssistantUiJsonContextTests`); and `ToUiEventsAsync_TrackedStream_LeavesMetadataNull` (in `ChatResponseUiExtensionsTests`), confirming the mapper never populates the field on a live tracked stream.
