# 0.7.0

**Tag:** `v0.7.0` · **Date:** 2026-08-18

All changes since [`v0.6.0`](v0.6.0.md).

The UI contract learns which MCP tool actually ran: for `ToolKind.McpTool` activities, `DisplayName` is now the raw MCP **tool** name ([#12](https://github.com/Andes-Software-Solutions/Andes.Extensions.AI/issues/12)) instead of duplicating the server name already carried by `Source`. A server exposing multiple tools previously produced indistinguishable activity cards — `{"kind":"ActivityStarted","toolKind":"McpTool","displayName":"Weather","source":"Weather"}` said *that* the "Weather" server acted, but not *which* of its tools executed, and the tool name (available on `ChatProgressUpdate.ToolName` throughout) was discarded by the projection with no way to recover it.

## Changed

- **MCP activities in the UI contract show the tool, not the server** (`Andes.Extensions.AI.UI/ChatResponseUiExtensions.cs`, [#12](https://github.com/Andes-Software-Solutions/Andes.Extensions.AI/issues/12)): a new kind-conditional rule (the private `ResolveDisplayName` helper) derives `DisplayName` on both projection paths — `ToUiEvent` (live `AssistantUiEvent`s) and `ToSnapshot`'s `ToActivity` (usage-report snapshots). For `ToolKind.McpTool` the value is the raw, model-designated tool name (including any renames, unformatted — clients apply their own presentation conventions), with the server name unchanged in `Source`; every other kind keeps the previous source-first behavior (`Source ?? ToolName`), so `Function` and `Agent` activities are untouched. Nested MCP children inside agents or tool bodies get the same treatment automatically — parent and child cards are produced by the same projection code. Core progress *headers* are unchanged: the default `"Calling {Server} MCP"` header text remains server-based.
  - **Semantic change, not a shape change.** The JSON wire format, `AssistantUiJsonContext`, and the TypeScript interfaces are byte-for-byte identical; only what travels in `displayName` for `toolKind: "McpTool"` differs. Before/after for a `get_forecast` call on the "Weather" server: `"displayName":"Weather","source":"Weather"` → `"displayName":"get_forecast","source":"Weather"`. Consumers that rendered the server name from an McpTool activity's `displayName` should read `source` instead.
- **Demo renderer surfaces both fields** (`samples/Andes.Extensions.AI.Demo/StatusRenderer.cs`): MCP activity cards now show the tool-name `DisplayName` with the owning server (`Source`) as a dim hint alongside the `mcp` badge, skipped when the two coincide.
- **Docs updated for the new semantics**: [UI status contract](../docs/ui.md) rewrites the mapper's clean-name rule and the [Clean names, not composed headers](../docs/ui.md#clean-names-not-composed-headers) walkthrough (tool `get_forecast` on "Andes Test MCP" → `DisplayName: "get_forecast"`, `Source: "Andes Test MCP"`, `Kind: McpTool`); [Architecture](../docs/architecture.md) refreshes its UI-contract example; the UI package README and the shipped `typescript/andes-assistant-ui.ts` doc-comments state the per-kind `displayName` semantics.
- **All four packages version in lockstep at 0.7.0**; the satellites depend on core `>= 0.7.0`. No dependency-pin changes.

## Verification

New unit coverage pins the semantics on every path: `ChatResponseUiExtensionsTests.ToUiEventsAsync_McpTool_DisplayNameIsToolNameAndSourceIsServerName` (live events — `ActivityStarted` and `ActivityCompleted` both carry the tool name with the server in `Source`), `ChatResponseUiExtensionsTests.ToSnapshot_McpTool_ActivityCardShowsToolNameWithServerSource` (the usage-report path through `ToActivity`), and `LiveNestedActivityTests.ToStatusSnapshotsAsync_NestedMcpScopeInsideTool_ChildCardShowsToolName` (a nested MCP child scope renders its tool name on the child card). The former combined McpTool/Agent theory is split so `ToUiEventsAsync_AgentTool_DisplayNameIsSourceWithNoKindWordRepeat` pins that `Agent` activities are unchanged (`DisplayName` = `Source` = agent name), and the `AssistantUiJsonContextTests` fixture now serializes an McpTool activity as `"displayName":"get_forecast"` with `"source":"Andes Test MCP"`.
