# 0.14.0

**Tag:** `v0.14.0` · **Date:** 2026-11-09

All changes since [`v0.13.0`](v0.13.0.md).

A dependency-floor release with no source changes and no public API changes. The Agent satellite's floor rises to `Microsoft.Agents.AI` 1.28.0, the MCP satellite's floor rises to `ModelContextProtocol.Core` 2.4.0, and the satellites depend on core `>= 0.14.0`. All four packages ship at 0.14.0 in lockstep. No Dependabot PR was open when this release was cut (`gh pr list` returned none), so it supersedes nothing.

## Changed

- **`Microsoft.Agents.AI` 1.27.0 → 1.28.0** (`Directory.Packages.props`): the Agent satellite's new floor, `Microsoft.Agents.AI >= 1.28.0`. Upstream `dotnet-1.28.0` (github.com/microsoft/agent-framework, 2026-11-06) lists these breaking items: A2A hosting registration (#10037), A2A identity options (#10113), CodeAct redacted host-tool errors (#9973), GitHub Copilot file hooks off by default (#10121), a declarative workflow HTTP allowlist (#9841), declarative MCP per-invocation clients (#9722), the declarative Foundry `AzureAgentProvider` renamed to `FoundryAgentProvider` (#10098), and workflow observability span names and payload attributes (#9899, #9994). None touch the APIs the Agent satellite calls: `AIAgentBuilder.Use(...)`, `AsAIFunction(...)`, `DelegatingAIAgent.RunCoreAsync`/`RunCoreStreamingAsync`, or `AgentResponse.Usage`. Version 1.28.0 declares `Microsoft.Extensions.AI` 10.11.0 and `Microsoft.Extensions.AI.Abstractions` 10.11.0, which equal the repo's pins, so transitive pinning causes no downgrade.
- **`ModelContextProtocol` and `ModelContextProtocol.Core` 2.3.0 → 2.4.0** (`Directory.Packages.props`): the MCP satellite's new floor, `ModelContextProtocol.Core >= 2.4.0`. The two move together because `ModelContextProtocol` 2.4.0 pins Core `[2.4.0]` exactly.
  - **This skips 2.3.1** (2026-11-03), a security fix ("Harden authenticated stateful MCP sessions") whose source changes are only in `ModelContextProtocol.AspNetCore`, which this repo does not reference.
  - Upstream `v2.4.0` (github.com/modelcontextprotocol/csharp-sdk, 2026-11-07) adds experimental MCP Skills in a new `ModelContextProtocol.Extensions.Skills` package, which this repo does not reference. It also hardens OAuth (#1952 makes the legacy metadata fallback opt-in; #1968, #1967, #1891), fixes dropped notifications and cancellation when a request is canceled (#1917, relevant to the satellite's progress-notification bridge; all MCP progress tests pass), cancels subscriptions and listen requests when the transport stops (#1933), keeps `server/discover` probes from committing the negotiated protocol version (#1956), falls back to SSE on a 405 with a JSON-RPC body (#1849), fixes legacy output schemas for delegating server tools (#1928), and makes MCP Apps match protocol property names case-sensitively (#1934).
  - The abstract `McpClient` type is unchanged between v2.3.1 and v2.4.0, so the hand-rolled test fake `tests/Andes.Extensions.AI.Mcp.Unit.Test/Infrastructure/ServerInfoOnlyMcpClient.cs` compiles unchanged.
  - `ModelContextProtocol.Core` 2.4.0 declares `Microsoft.Extensions.AI.Abstractions` 10.11.0, which equals the repo's pin, so there is no downgrade. It also declares `Microsoft.Extensions.Logging.Abstractions` 10.0.14.
- **`xunit.v3` 4.0.2 → 4.0.3** (`Directory.Packages.props`): a test-only patch. The xunit.net v3 4.0.3 release notes list a fix for crash detection wrongly reporting premature crashes (xunit/xunit#3656), a fix for interface "test implementation template" methods reported as invalid overloads (#3655), `DateOnly` display in theory values (#3653), a Native AOT assembly-fixture registration fix, a fix for corrupted or missing results files (#3651), better Microsoft Testing Platform argument validation (#3654), and reworked Microsoft Testing Platform cleanup-failure reporting. Nothing shipped references it.
- **`global.json` SDK 10.0.402 → 10.0.403** (runtime 10.0.14, released 2026-10-25, flagged security in the .NET release-metadata index). `rollForward: latestFeature` and the `test` section are unchanged. CI already used 10.0.403 through `actions/setup-dotnet` resolving `latestFeature` to the 10.0 channel, so this makes the patched SDK the stated minimum.
- **Consumer-visible floors, read from the packed nuspecs:**
  - Core: `Microsoft.Extensions.AI >= 10.11.0` and `Microsoft.Extensions.AI.Abstractions >= 10.11.0` (unchanged).
  - Mcp: core `>= 0.14.0`, `ModelContextProtocol.Core >= 2.4.0` (was 2.3.0), and both Microsoft.Extensions.AI packages `>= 10.11.0`.
  - Agent: core `>= 0.14.0`, `Microsoft.Agents.AI >= 1.28.0` (was 1.27.0), and both Microsoft.Extensions.AI packages `>= 10.11.0`.
  - UI: core `>= 0.14.0` and both Microsoft.Extensions.AI packages `>= 10.11.0`.
- **Transitive moves per shipped project** (`dotnet list package --include-transitive` diff, before versus after): core and UI have none. Mcp moves `ModelContextProtocol.Core` 2.3.0 → 2.4.0, plus `Microsoft.Extensions.DependencyInjection.Abstractions` and `Microsoft.Extensions.Logging.Abstractions` 10.0.13 → 10.0.14. Agent moves `Microsoft.Agents.AI` and `Microsoft.Agents.AI.Abstractions` 1.27.0 → 1.28.0, plus `Microsoft.Extensions.AI.Evaluation` 10.10.0 → 10.11.0.
- **Every other pin is unchanged:**
  - `OpenAI` stays at 2.14.0. Version 2.15.0 exists on nuget.org, but `Microsoft.Extensions.AI.OpenAI` 10.11.0, still the latest, declares OpenAI 2.14.0 in its nuspec, so the pin comment and the Dependabot ignore rule still apply.
  - `Microsoft.Extensions.AI`, `.Abstractions`, and `.OpenAI` (10.11.0), `Microsoft.Extensions.Configuration.Binder` / `.Json` and `Microsoft.Extensions.Hosting` (10.0.14), `Microsoft.NET.Test.Sdk` (18.11.0), `xunit.runner.visualstudio` (4.0.1), `Spectre.Console` (0.57.2), and `Azure.AI.OpenAI` (2.1.0) were already the latest stable.
- **Docs updated to the actual floors**: [`docs/agents.md`](../docs/agents.md) now states core `>= 0.14.0` and `Microsoft.Agents.AI >= 1.28.0` (previously `>= 0.13.0` / `>= 1.27.0`); [`docs/mcp.md`](../docs/mcp.md) states core `>= 0.14.0` and `ModelContextProtocol.Core >= 2.4.0` (previously `>= 0.13.0` / `>= 2.3.0`); [`docs/ui.md`](../docs/ui.md) states core `>= 0.14.0` (previously `>= 0.13.0`). The `AGENTS.md` project section now says the four packages are at 0.14.0.
- **All four packages version in lockstep at 0.14.0; the satellites depend on core `>= 0.14.0`.**
