# 0.10.0

**Tag:** `v0.10.0` · **Date:** 2026-09-21

All changes since [`v0.9.0`](v0.9.0.md).

Another dependency-floor release, same nature as 0.9.0: the core package's floor rises to `Microsoft.Extensions.AI` 10.10.0, which pulls the Agent satellite's floor up to `Microsoft.Agents.AI` 1.22.0 (its nuspec depends on the same `Microsoft.Extensions.AI` 10.10.0), the SDK band in `global.json` moves to 10.0.401, `OpenAI` deliberately stays at 2.13.0 with the reason rewritten to reflect an experimental-type rename in 2.14.0, and Dependabot's own `nuget-stable` group already landed seven of the nine moving pins in commit `363dec4` — no source changed, no public API changed, and all four packages ship at 0.10.0 in lockstep with the satellites depending on core `>= 0.10.0`.

## Changed

- **`Microsoft.Extensions.AI` 10.9.0 → 10.10.0** (`Directory.Packages.props`, uncommitted): the core package's floor — the packed nuspec will read `Microsoft.Extensions.AI >= 10.10.0`. Upstream `v10.10.0` (github.com/dotnet/extensions, published 2026-09-14) removed the deprecated/experimental OpenAI Assistants API support (it lived behind `OPENAI001`, which this repo never used), tightened image-options null handling, and made evaluation quality metrics fail closed when a score is missing — none of it touches the middleware surface this repo builds on. Its own nuspec depends on `Microsoft.Extensions.AI.Abstractions` 10.10.0 (already picked up by Dependabot below) and the 10.0.12 runtime abstractions.
- **`Microsoft.Extensions.AI.Abstractions` 10.9.0 → 10.10.0 and `Microsoft.Extensions.AI.OpenAI` 10.9.0 → 10.10.0** (`Directory.Packages.props`, commit `363dec4`, "Bump the nuget-stable group with 7 updates", dependabot[bot], 2026-09-19): `Microsoft.Extensions.AI.Abstractions` is the UI package's floor, so its packed nuspec now reads `Microsoft.Extensions.AI.Abstractions >= 10.10.0`. `Microsoft.Extensions.AI.OpenAI` is consumed only by the Responses sample and the core integration-test project — nothing shipped references it — but its 10.10.0 nuspec is the reason the `OpenAI` pin below moved too: it now declares an open floor (`OpenAI >= 2.13.0`) instead of 10.9.0's closed range.
- **`Microsoft.Agents.AI` 1.20.0 → 1.22.0** (`Directory.Packages.props`, uncommitted): the Agent satellite's new floor — the packed nuspec will read `Microsoft.Agents.AI >= 1.22.0`. Upstream shipped this in two releases (github.com/microsoft/agent-framework): `dotnet-1.21.0` (2026-09-11) and `dotnet-1.22.0` (2026-09-18). 1.22.0's breaking changes — improved replay support with approval binding, MCP sessions scoped per invocation, sticky Foundry delegated user identity — and 1.21.0's — the `file_access_read_lines` line-numbering contract moving onto `AgentFileStore`, clarified A2A run modes, ZIP-only MCP skill archives, isolated LocalCodeAct subprocess environments — none touch the APIs the Agent satellite calls: `AIAgentBuilder.Use(...)` function-invocation middleware, `AsAIFunction(functionOptions, session)`, `DelegatingAIAgent.RunCoreAsync`/`RunCoreStreamingAsync`, `AgentResponse.Usage`, or the `GetService(typeof(ChatClientAgent))` probe. 1.22.0's nuspec depends on `Microsoft.Extensions.AI` 10.10.0, which is why this bump had to ride along with the core floor above rather than land through Dependabot's own PR. A transitive floor moves as a result (not pinned by this repo): `Microsoft.Agents.AI.Abstractions` 1.20.0 → 1.22.0.
- **`Microsoft.Extensions.Configuration.Binder` / `.Json` and `Microsoft.Extensions.Hosting` 10.0.11 → 10.0.12, `Microsoft.NET.Test.Sdk` 18.9.0 → 18.10.1** (`Directory.Packages.props`, commit `363dec4`): patch/minor bumps referenced only by the sample apps and test projects — nothing shipped references them.
- **`OpenAI` held at 2.13.0** (bumped from 2.12.0 in commit `363dec4`, then deliberately not moved further to 2.14.0 which is also on nuget.org): the `Microsoft.Extensions.AI.OpenAI` 10.10.0 assembly carries a metadata reference to `OpenAI.Responses.GlobalMcpToolCallApprovalPolicy`, and OpenAI 2.14.0's changelog renames that type to `DefaultMcpToolCallApprovalPolicy` under "breaking changes in experimental APIs" — `ResponsesClient` is still `[Experimental("OPENAI001")]` in 2.13.0. Floating `OpenAI` past the version `Microsoft.Extensions.AI.OpenAI` was compiled against therefore risks a `TypeLoadException` on the Responses tool-conversion path, the path exercised by the Responses sample and the Responses integration test. The comment above the pin in `Directory.Packages.props` was rewritten to explain this (uncommitted), and the `.github/dependabot.yml` comment on the `OpenAI` ignore rule was rewritten to match (uncommitted) — the ignore rule itself is unchanged. The pin is consumed only by the Responses sample and the core integration-test project; nothing shipped references it.
- **Every other pin was already the latest stable and is unchanged**: `ModelContextProtocol` / `.Core` 2.2.0, `Azure.AI.OpenAI` 2.1.0, `Spectre.Console` 0.57.2, `xunit` 2.9.3, `xunit.runner.visualstudio` 4.0.0, `Xunit.SkippableFact` 1.5.85, `coverlet.collector` 10.0.1. The `xunit.v3` migration remains deferred.
- **`global.json`**: SDK `10.0.400` → **`10.0.401`** (uncommitted; `rollForward: latestFeature` unchanged), the latest .NET 10 SDK (`latest-sdk` 10.0.401 alongside runtime 10.0.12, released 2026-09-08) per the .NET releases index. `nuget.yml` reads `global-json-file`, so CI follows without a workflow change.
- **Transitive floors that moved as a side effect** (from a before/after diff of `dotnet list package --include-transitive`; none are pinned by this repo, beyond the `Microsoft.Agents.AI.Abstractions` move already noted above): `Microsoft.Extensions.AI.Evaluation` 10.9.0 → 10.10.0, `Microsoft.Extensions.VectorData.Abstractions` 10.8.2 → 10.10.0, `Microsoft.Extensions.Compliance.Abstractions` 10.5.0 → 10.10.0, `Microsoft.Extensions.ObjectPool` 10.0.6 → 10.0.12, `Microsoft.Extensions.FileSystemGlobbing` 10.0.11 → 10.0.12, and the runtime abstractions `Microsoft.Extensions.Caching.Abstractions` / `DependencyInjection.Abstractions` / `Logging.Abstractions` / `Primitives` / `System.Numerics.Tensors` 10.0.11 → 10.0.12.
- **Docs updated to the actual floors** (uncommitted): [`docs/agents.md`](../docs/agents.md) now states core `>= 0.10.0` and `Microsoft.Agents.AI >= 1.22.0` (previously `>= 0.9.0` / `>= 1.20.0`); [`docs/mcp.md`](../docs/mcp.md) now states core `>= 0.10.0` (previously `>= 0.9.0`); [`docs/ui.md`](../docs/ui.md) now states core `>= 0.10.0` (previously `>= 0.9.0`). `.claude/CLAUDE.md` project memory now says the four packages are at 0.10.0, and its Responses-API experimental note now cites OpenAI 2.13. The `OPENAI001` `NoWarn` comments in `samples/Andes.Extensions.AI.Demo.Responses` and `tests/Andes.Extensions.AI.Integration.Test` now say 2.13.0 instead of 2.12.0.
- **All four packages version in lockstep at 0.10.0; the satellites depend on core `>= 0.10.0`.** No public API changes, no code changes.

## Verification

No new tests — nothing in the shipped code changed. The release was verified the way `nuget.yml` builds it. `dotnet restore` is clean (no NU1605/NU1608 or other NuGet diagnostics), and a before/after diff of `dotnet list package --include-transitive` shows only the expected moves listed above. `dotnet build Andes.Extensions.slnx --configuration Release` succeeds with 0 warnings and 0 errors (warnings as errors — the 10.10.0 / 1.22.0 bumps surfaced no obsoletions or analyzer diagnostics), and `dotnet format --verify-no-changes` reports nothing. `dotnet test Andes.Extensions.slnx --configuration Release --no-build` passed 172 of 172 with 0 skipped: 162 unit tests (core 82, UI 31, Agent 28, MCP 21) and 10 Azure OpenAI integration tests run for real against the configured deployments (core 5, including the Responses API reasoning test — the end-to-end check of `Microsoft.Extensions.AI.OpenAI` 10.10.0 + `OpenAI` 2.13.0; MCP 2; Agent 3 — the end-to-end check of `Microsoft.Agents.AI` 1.22.0). `dotnet pack` of the four projects (Release, `--no-build`) produced a 0.10.0 `.nupkg` and `.snupkg` for each; the nuspecs inside carry version 0.10.0, `readme=README.md`, `icon=icon.png` (the UI package also ships `typescript/andes-assistant-ui.ts`), and the expected floors: core → `Microsoft.Extensions.AI >= 10.10.0`; Mcp → core `>= 0.10.0` and `ModelContextProtocol.Core >= 2.2.0`; Agent → core `>= 0.10.0` and `Microsoft.Agents.AI >= 1.22.0`; UI → core `>= 0.10.0` and `Microsoft.Extensions.AI.Abstractions >= 10.10.0`. `dotnet list package --outdated` lists nothing except the deliberately held `OpenAI` 2.14.0.
