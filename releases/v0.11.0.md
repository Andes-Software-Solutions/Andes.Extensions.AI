# 0.11.0

**Tag:** `v0.11.0` · **Date:** 2026-10-07

All changes since [`v0.10.0`](v0.10.0.md).

Another dependency-floor release, same nature as 0.9.0 and 0.10.0: the Agent satellite's floor rises to `Microsoft.Agents.AI` 1.24.0, `Microsoft.Extensions.AI.Abstractions` rises to the 10.10.1 patch release (which lifts that floor in all four packages), and the deliberate `OpenAI` 2.13.0 hold from 0.10.0 is lifted now that `Microsoft.Extensions.AI.OpenAI` 10.10.1 is built against 2.14.0 — no source changed, no public API changed, and all four packages ship at 0.11.0 in lockstep with the satellites depending on core `>= 0.11.0`. This release supersedes Dependabot PR #21 ("Bump the nuget-stable group with 4 updates", opened 2026-10-03), which carries four of the five pin moves below (`coverlet.collector`, `Microsoft.Extensions.AI.Abstractions`, `Microsoft.Extensions.AI.OpenAI`, `OpenAI`) but not `Microsoft.Agents.AI` and not the rewritten pin comment.

## Changed

- **`Microsoft.Extensions.AI.Abstractions` 10.10.0 → 10.10.1 and `Microsoft.Extensions.AI.OpenAI` 10.10.0 → 10.10.1** (`Directory.Packages.props`, uncommitted): upstream `v10.10.1` (github.com/dotnet/extensions, published 2026-09-25) shipped only these two packages. Its notes: it "fixes two OpenAI integration issues: a TypeLoadException on tool-carrying Responses API calls and a streaming crash against third-party OpenAI-compatible endpoints, by upgrading the OpenAI SDK to 2.14.0" (dotnet/extensions#7761, issue #7760). There is no `Microsoft.Extensions.AI` 10.10.1, so that pin stays at 10.10.0. `Microsoft.Extensions.AI.OpenAI` is consumed only by the Responses sample and the core integration-test project; nothing shipped references it.
- **Consumer-visible floor: `Microsoft.Extensions.AI.Abstractions >= 10.10.1` in all four packages.** The repo sets `CentralPackageTransitivePinningEnabled=true`, so the pinned `Microsoft.Extensions.AI` and `Microsoft.Extensions.AI.Abstractions` versions are emitted as direct dependencies in every package's nuspec (the published 0.10.0 nuspecs already have this shape). The Abstractions floor therefore rises from 10.10.0 to 10.10.1 in core, Mcp, Agent, and UI, not only in the UI package whose source references it directly. The `Microsoft.Extensions.AI` floor stays at 10.10.0.
- **`Microsoft.Agents.AI` 1.22.0 → 1.24.0** (`Directory.Packages.props`, uncommitted): the Agent satellite's new floor — the packed nuspec reads `Microsoft.Agents.AI >= 1.24.0`. Upstream shipped this in two releases (github.com/microsoft/agent-framework): `dotnet-1.23.0` (2026-10-01) and `dotnet-1.24.0` (2026-10-07). 1.23.0's nuspec depends on `Microsoft.Extensions.AI.Abstractions` 10.10.1 (and `Microsoft.Extensions.AI` 10.10.0), which is why it could not move while Abstractions was pinned at 10.10.0 — the bump had to ride along with the Abstractions move above. 1.23.0's breaking changes — #8754 "Better support tool changes between runs" (`ChatClientAgent` tool-name validation and pending-call handling), #8730 (bumps Azure.AI.Projects 3.0.0-beta.3, OpenAI 2.14.0, and the Microsoft.Extensions.AI 10.10.1 patch packages), #8200 (allow list for configuration keys), #8641 (enforce approval response binding), and #8423 (DevUI approval continuation) — do not touch the APIs the Agent satellite calls: `AIAgentBuilder.Use(...)` function-invocation middleware, `AsAIFunction(...)`, `DelegatingAIAgent.RunCoreAsync`/`RunCoreStreamingAsync`, or `AgentResponse.Usage`. Two non-breaking changes were checked against the satellite as well: #8615 lets function middleware replace `FunctionInvocationContext.Function`, but the satellite's `ReportFunctionCallAsync` (`AgentToolTrackingExtensions`) only reads `context.Function.Name`, so it is unaffected; and 1.24.0's #9017 passes the already-materialized request messages to `RunCoreAsync`/`RunCoreStreamingAsync`, which is transparent to the internal `UsageReportingAIAgent`. A transitive floor moves as a result (not pinned by this repo): `Microsoft.Agents.AI.Abstractions` 1.22.0 → 1.24.0.
- **`OpenAI` 2.13.0 → 2.14.0; the 0.10.0 hold is lifted** (`Directory.Packages.props`, uncommitted): 0.10.0 held `OpenAI` at 2.13.0 because `Microsoft.Extensions.AI.OpenAI` 10.10.0 was compiled against a type that 2.14.0 renames (`GlobalMcpToolCallApprovalPolicy` → `DefaultMcpToolCallApprovalPolicy`, listed under "breaking changes in experimental APIs"), risking a `TypeLoadException` on the Responses tool-conversion path. `Microsoft.Extensions.AI.OpenAI` 10.10.1 is built against 2.14.0 and its nuspec declares `OpenAI >= 2.14.0` — exactly the condition the hold named — and the `TypeLoadException` is the one 10.10.1 fixes. The comment above the pin in `Directory.Packages.props` was rewritten to say the pin tracks the `OpenAI` version `Microsoft.Extensions.AI.OpenAI` 10.10.1 compiles against, and keeps the rule that the two bump only together. `.github/dependabot.yml` is unchanged: its `OpenAI` minor/major ignore rule and comment remain accurate. Reflection over the restored `OpenAI` 2.14.0 assembly confirms `OpenAI.Responses.ResponsesClient` and `OpenAIClient.GetResponsesClient()` are still `[Experimental("OPENAI001")]`, so the `NoWarn OPENAI001` stays; the comments in `samples/Andes.Extensions.AI.Demo.Responses` and `tests/Andes.Extensions.AI.Integration.Test` now say 2.14.0 (uncommitted). The pin is consumed only by the Responses sample and the test projects; nothing shipped references `OpenAI`.
- **`coverlet.collector` 10.0.1 → 10.1.0** (`Directory.Packages.props`, uncommitted): referenced only by the test projects. Upstream 10.1.0 notes: "Publish Microsoft.Testing.Platform coverage messages from coverlet.MTP" (#2019).
- **Every other pin was already the latest stable and is unchanged**: `Microsoft.Extensions.AI` 10.10.0, `ModelContextProtocol` / `.Core` 2.2.0, `Microsoft.Extensions.Configuration.Binder` / `.Json` and `Microsoft.Extensions.Hosting` 10.0.12, `Microsoft.NET.Test.Sdk` 18.10.1, `Azure.AI.OpenAI` 2.1.0 (newer versions are beta only), `Spectre.Console` 0.57.2, `xunit` 2.9.3, `xunit.runner.visualstudio` 4.0.0, `Xunit.SkippableFact` 1.5.85. The `xunit.v3` migration remains deferred. `global.json` stays at SDK 10.0.401, still the latest .NET 10 SDK per the .NET releases index (latest runtime 10.0.12, released 2026-09-08).
- **Transitive floors that moved as a side effect** (from a before/after diff of `dotnet list package --include-transitive`; none are pinned by this repo, beyond the `Microsoft.Agents.AI.Abstractions` move already noted above). Via `OpenAI` 2.14.0, in sample and test projects only (nothing shipped): `System.ClientModel` 1.14.0 → 1.15.0 and `System.Memory.Data` 10.0.3 → 10.0.9; in the projects that previously resolved them at 10.0.3 (the Responses demo and the core and Agent integration tests), `Microsoft.Extensions.Diagnostics.Abstractions`, `Microsoft.Extensions.Hosting.Abstractions`, and `Microsoft.Extensions.Options` 10.0.3 → 10.0.9.
- **Docs updated to the actual floors** (uncommitted): [`docs/agents.md`](../docs/agents.md) now states core `>= 0.11.0` and `Microsoft.Agents.AI >= 1.24.0` (previously `>= 0.10.0` / `>= 1.22.0`); [`docs/mcp.md`](../docs/mcp.md) now states core `>= 0.11.0` (previously `>= 0.10.0`); [`docs/ui.md`](../docs/ui.md) now states core `>= 0.11.0` (previously `>= 0.10.0`). The `AGENTS.md` project section now says the four packages are at 0.11.0, and its Responses-API experimental note now cites OpenAI 2.14.
- **All four packages version in lockstep at 0.11.0; the satellites depend on core `>= 0.11.0`.** No public API changes, no code changes.

## Verification

No new tests — nothing in the shipped code changed. The release was verified the way `nuget.yml` builds it. `dotnet restore` is clean (no NU1605/NU1608/NU1109 or other NuGet diagnostics), and a before/after diff of `dotnet list package --include-transitive` shows only the expected moves listed above. `dotnet build Andes.Extensions.slnx --configuration Release` succeeds with 0 warnings and 0 errors (warnings as errors — the bumps surfaced no obsoletions or analyzer diagnostics), the build outputs reference `OpenAI` 2.14.0, `Microsoft.Extensions.AI.OpenAI` 10.10.1, `Microsoft.Extensions.AI.Abstractions` 10.10.1, and `Microsoft.Agents.AI` 1.24.0, and `dotnet format --verify-no-changes` reports nothing. `dotnet test Andes.Extensions.slnx --configuration Release --no-build` passed 172 of 172 with 0 skipped: 162 unit tests (core 82, UI 31, Agent 28, MCP 21) and 10 Azure OpenAI integration tests run for real against the configured deployments (core 5, including the Responses API reasoning test — the end-to-end check of `Microsoft.Extensions.AI.OpenAI` 10.10.1 + `OpenAI` 2.14.0; MCP 2; Agent 3 — the end-to-end check of `Microsoft.Agents.AI` 1.24.0). `dotnet pack` of the four projects (Release, `--no-build`) produced a 0.11.0 `.nupkg` and `.snupkg` for each; the nuspecs inside carry version 0.11.0, `readme=README.md`, `icon=icon.png` (the UI package also ships `typescript/andes-assistant-ui.ts`), and the expected floors: core → `Microsoft.Extensions.AI >= 10.10.0` and `Microsoft.Extensions.AI.Abstractions >= 10.10.1`; Mcp → core `>= 0.11.0`, `ModelContextProtocol.Core >= 2.2.0`, `Microsoft.Extensions.AI >= 10.10.0`, and `Microsoft.Extensions.AI.Abstractions >= 10.10.1`; Agent → core `>= 0.11.0`, `Microsoft.Agents.AI >= 1.24.0`, `Microsoft.Extensions.AI >= 10.10.0`, and `Microsoft.Extensions.AI.Abstractions >= 10.10.1`; UI → core `>= 0.11.0`, `Microsoft.Extensions.AI.Abstractions >= 10.10.1`, and `Microsoft.Extensions.AI >= 10.10.0`. `dotnet list package --outdated` lists nothing for any project.
